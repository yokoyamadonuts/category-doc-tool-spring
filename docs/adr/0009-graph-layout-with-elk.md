# 0009 グラフの配置と矢印の経路を ELK で求める

2026-10-23 採用

## 状況

カテゴリの文書と関係を、向きのあるグラフとして描く。描画は @xyflow/react、配置は自動で決めたい。

## 決定

- 配置は elkjs の階層型の配置で、左から右へ並べる。矢印の経路と、関係の名前の場所も ELK に求めさせる
- 矢印は React Flow の既定の曲線ではなく、ELK が引いた折れ線で描く
- ELK は Web Worker で動かす
- 恒等射はどの文書にもあるので描かず、省いた本数を添える
- 節点は動かせないようにする

## 理由

- 文書の関係は要件から設計へ、のように向きがあり、階層型の配置が読みやすい
- React Flow の既定の曲線は両端だけを見て引くので、層を1つ飛ばす矢印が間の節点を突き抜けて見えなくなった。ELK の経路は節点を避ける
- ELK の本体は 1.4MB ある。Worker に分けると、配置の計算で画面が固まらず、画面の JavaScript にも含まれない。グラフの画面の JavaScript は 1.6MB から 185KB になった

## 結果

- 節点を動かすと、配置のときに求めた矢印の経路とずれる。そのため動かせないようにした
- jsdom では描画を確かめにくい。配置を求める関数を純粋な関数に分け、矢印が間の節点を通らないことを単体テストで確かめ、描画は E2E と目視で確かめる
- テストの環境には Worker がないので、テストでは同期版の ELK を渡す

## 採らなかった案

- dagre: 軽いが、関係の名前の場所や直交の経路まで含めた配置の指定は ELK のほうが細かい
- React Flow の既定の配置と曲線のまま: 上のとおり、矢印が隠れる
